# Carina 0.8.22

Governed web access and conversation clarity release. This version gives the
agent a bounded way to read public HTTPS text while keeping network access
explicit, and removes duplicate question/tool receipts from the transcript.

## Highlights

- The agent can use `web.fetch` for known public HTTPS URLs instead of falling
  back to shell commands such as `curl` or `wget`.
- Web fetches require host-level approval in the default Ask mode. Redirects,
  credentials, non-public networks, binary responses, oversized bodies, and
  non-standard HTTPS ports are rejected.
- Fetched content is bounded and marked as untrusted data so a page cannot
  silently become agent instructions.
- Question prompts remain owned by the governance overlay. Their tool lifecycle
  no longer creates a duplicate Tool/Run entry after the user answers.
- Fetch activity has a dedicated transcript presentation that keeps the
  approved host visible without exposing the full URL in audit summaries.
- The model picker adds a provider shortcut and can find providers from their
  model names, with clearer search guidance.

## Upgrade notes

- Restart an active workspace runtime after upgrading so its daemon, kernel
  service, and TUI all load 0.8.22. Carina does not interrupt active tasks
  automatically.
- `web.fetch` is intentionally narrower than a browser. It reads public text or
  structured data from a known URL and does not support login flows, redirects,
  private hosts, or arbitrary downloads.
- Local source installs can run `make install`; packaged installs can use
  `carina update`, Homebrew, npm, or the release archive.
