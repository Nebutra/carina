# Carina 0.7.0

Minor release focused on first-run readiness, semantic tool feedback, bounded
streaming latency, and deterministic lifecycle replay across the daemon and
terminal UI.

## Highlights

### Daemon-owned readiness and continuity

- The daemon now returns an explicit execution-readiness snapshot for the
  active session, locale, provider, and model, so the TUI preserves a draft and
  routes back to the actionable setup step when submission is blocked.
- Reasoning effort follows the selected model's native capabilities and remains
  stable when switching between supported providers and models.
- Workspace startup prefers the most recent compatible session, improving cold
  resume without weakening session ownership or runtime checks.
- First-five-minute journey metrics record readiness and accepted execution
  milestones for operational diagnosis without exposing prompt content.

### Intent-first tool feedback

- Tool lifecycle events carry a normalized, bounded intent when the model
  supplies one.
- TUI tool rows prefer that intent as their primary fact while retaining paths,
  commands, and other concrete targets for inspection.
- Live lifecycle events and hydrated session replay produce the same intent
  projection; older events without intent continue to use the existing target
  summary.

### Bounded streaming feedback

- First token, tool start, approval wait, tool result, and completion feedback
  are measured independently against explicit UI budgets.
- The active spinner now uses an 80 ms deadline, stops when no animation is
  needed, and does not replay missed frames after a delayed draw.
- Feedback markers coalesce and deduplicate before presentation, keeping the
  retained terminal surface responsive under bursty streams.

### Canonical lifecycle replay

- Daemon lifecycle events now preserve canonical run and event identity through
  persistence, live delivery, reconnect, and replay.
- A single TUI lifecycle reducer rejects duplicate events and illegal terminal
  regressions instead of inventing success from unknown or out-of-order input.
- Tool and transcript reducers share deterministic transition rules, and legacy
  `task_id` payloads remain compatible at decode boundaries.
- Live and replay paths converge on the same semantic component identity and
  cursor contract, reducing duplicate cells and reconnect drift.

## Upgrade notes

- Restart long-running `carina-daemon` processes after upgrading so the CLI,
  TUI, daemon, integrations, and SDK compatibility checks all advertise the
  `0.7.0` runtime contract.
- Standalone installs can use `carina update`. Homebrew installs use
  `brew update && brew upgrade carina` after the release workflow updates the
  official tap.
