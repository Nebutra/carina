# Carina 0.6.6

Patch release on the 0.6 line. Focus: a more legible coding-agent journey,
one runtime-owned command catalog, and a clearer first product impression.

## Highlights

### Runtime-owned command discovery

- The TUI now builds slash-command suggestions from runtime capabilities
  instead of maintaining a disconnected local command list.
- Built-in, daemon, workflow, skill, and MCP commands share one searchable
  palette with localized labels and source-aware presentation.
- Command availability follows the active session and execution state, so the
  interface does not advertise actions the runtime cannot honor.

### Visible edit lifecycle

- Transcript events preserve the Edit tool lifecycle as a semantic component
  rather than reducing file work to anonymous log lines.
- Patch and file-change events retain their runtime identity so operators can
  follow what changed and connect the visible result to audit evidence.
- Tool status, completion, and failure states remain distinct instead of being
  flattened into generic progress output.

### Documentation delivery

- The homepage now keeps the install path inside the hero and presents the
  governed terminal as the primary product surface.
- Header and rail geometry reserve stable space across the first viewport;
  release Lighthouse checks pass without lowering performance or layout-shift
  thresholds.
- Current installation and release references are aligned across English,
  Simplified Chinese, and Japanese documentation.

## Upgrade notes

- Restart long-running `carina-daemon` processes after upgrading so CLI, TUI,
  and daemon all advertise the `0.6.6` runtime contract.
- Standalone installs can use `carina update`. Homebrew installs use
  `brew update && brew upgrade carina` after the release workflow updates the
  official tap.
