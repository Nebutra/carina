# Carina 0.8.12

Patch release. End-to-end honesty for model effort and operator-facing failures
(follow-on to 0.8.10–0.8.11).

## Highlights

### Inventory ↔ wire effort contract

- Model inventory only advertises reasoning effort levels that a wire encoder
  can send. Catalog-only options without a known protocol family no longer
  appear as Tab controls that later fail at submit.
- Task submit and session model preference **remap or clear** stale effort
  instead of hard-failing the turn when switching models.
- Ops overrides still encode as OpenAI-compatible `reasoning.effort` when the
  family is otherwise unknown.
- Typed error codes: `provider_reasoning_effort_unsupported` /
  `provider_reasoning_effort_invalid` with operator copy.
- Regression: every inventory effort for OpenAI/Codex/Azure/xAI/Gemini routes
  must encode without adapter rejection.

### Operator UI

- Failure block titles localize (执行失败 / Approval denied / …).
- Defense-in-depth humanize for residual effort adapter strings.
- Provider search cursor uses cell width for CJK queries.

## Upgrade notes

- Restart `carina-daemon` and relaunch the TUI.
- Standalone: `carina update`.
