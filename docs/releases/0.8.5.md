# Carina 0.8.5

Patch release on the 0.8 line. Focus: unblock TUI when a non-importable
CC Switch managed proxy was the only "available" provider.

## Highlights

### Provider readiness / startup routing

- CC Switch routes marked `explain_unavailable` or non-importable are no
  longer treated as runnable even when a stale bearer remains in the local
  credential store (the Mox managed-proxy case with zero models).
- Placeholder inventory defaults such as `default` no longer make the
  model-router reasoner look ready.
- When a configured route has no compatible models, the TUI returns to the
  **Provider** picker with a clear notice instead of locking into the
  Diagnostic-only screen (redetect/exit only).

## Upgrade notes

- Restart long-running `carina-daemon` after upgrade so inventory uses the
  new readiness rules under the `0.8.5` runtime.
- If you still see a stale managed-proxy credential, import a saved profile
  that has a reusable token, or remove `ccswitch-codex-managed-proxy` from
  `~/.carina/auth.json` and redetect.
- Standalone: `carina update`. Homebrew: `brew update && brew upgrade carina`
  after the release workflow updates the tap.
