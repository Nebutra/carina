Sub-agents run delegated tasks under a **strict subset** of the parent session's capabilities. Spawn is mediated by the `SubagentSpawn` capability.

## Spawn resource shape

```
agent:NAME:profile:PROFILE
```

Built-in policy requires approval by default. The child's capabilities are attenuated **before** the spawn completes — children cannot mint new authority upward.

## Agent tool

```json title="spawn.json"
{"tool":"spawn","agent":"scout","task":"Map module boundaries"}
```

- Declarative manifest per agent
- Per-agent tool allow-list
- `"tasks":[…]` runs multiple tasks in parallel

Set `"background":true` to return durable job handles after governed child
setup instead of waiting for summaries:

```json title="spawn-background.json"
{"tool":"spawn","agent":"scout","task":"Map module boundaries","background":true,"intent":"Delegate bounded repository mapping"}
```

Background fan-out is limited to eight jobs. The parent can use `job.list`,
`job.wait` (`any` or `all`, up to 30 seconds), and `job.cancel`. These tools
only resolve jobs in the caller's tenant, workspace ownership chain, session
boundary, and root run lineage. Job results expose bounded summaries, status,
timestamps, usage, and patch artifact references, never child prompts,
reasoning, transcripts, or raw tool observations.

After a daemon restart, terminal jobs remain terminal. A formerly live job is
reconciled through the ordinary continuity policy and is never reported as
still running merely because its last persisted state was live.

## Patterns

| Pattern | Description |
| --- | --- |
| Research fork | Read-heavy child gathers context |
| Patch worker | Write-scoped child applies a bounded edit set |
| Review swarm | Parallel reviewers with no write access |
| Workflow steps | Each workflow step is an isolated, attenuated subagent |

## Why attenuate

1. Unconstrained children amplify blast radius
2. Audit records nest under the parent turn
3. Parent remains the recovery and approval authority
